# EasyFly Mesh 通信

`mesh_peer` 在显式 IPv4 UDP 邻居之间建立最多 16 个已知节点的多跳观测网络。
每个节点使用 M-03 的独立 Ed25519 身份，所有成员公钥预先配置；中继原样转发
已签名报文，不能修改源身份、目的身份、会话、序号、源时间或数据。
此模块负责应用层组网与路由；无线电、Wi-Fi/以太网驱动和实际外场链路验收另行进行。

## 配置和启动

为每个节点分别执行 `ros2 run easyfly_udp_protocol udp_keygen /absolute/new-keys`。
私钥保持本人所有、0600，不复制给其他节点；将公钥传给需要信任该成员的节点。
以 `config/mesh.example.json` 为模板，为每台机器写独立 JSON：

- `bind` 为本机明确的单播 IPv4 地址和 UDP 端口。
- `private_key_file` 和每个 `public_key_file` 均为绝对路径。
- `input_topic` 是本机原生 `nav_msgs/Odometry` 输入，最大转发 20 Hz。
- `peers` 包含全部远端可信成员，每个 `output_topic` 是独立的远端里程计出口。
- 能直接到达的成员设置 `endpoint: [IPv4, port]`；多跳成员设置 `null`。
  每条直连链路需在双方配置；不会自动信任广播发现的未知设备。

```bash
ros2 run easyfly_mesh_comm mesh_peer --ros-args \
  -p config_file:=/absolute/mesh-a.json
ros2 topic echo /mesh_peer/status
```

同机多实例使用不同节点名、端口、输入和出口话题。部署前同步各机器 UTC：
报文过期使用 UTC，观测新鲜度使用相同时间基准的 ROS 时钟。仿真需各节点接同一
仿真时钟；冻结或回退不会用新心跳续期旧观测，回退锁存后需新会话。

## 路由与恢复契约

每 0.5 s 发送随机挑战，只有匹配的签名响应才证明双向直连；1.5 s 未响应即失效。
每 0.4 s 发布签名链路状态，链路必须在双方新鲜声明中存在才进入最短跳数路由；
同长路径按节点 ID 稳定选择。中继不延长 1.5 s 报文寿命，逐源防重放阻止转发环路。
路径变化时自动使用新的有效路径；全网分区则丢弃无路由的新样本，不缓存旧数据重发。
节点重启使用新 UUID 会话，退役会话不能再次接管。完整位姿、速度、双协方差、
原始 source stamp、frame_id 和 child_frame_id 均保留，接收数据不自动重命名坐标系。
每个出口按配置公钥隔离；调用方须显式变换坐标后才可融合。

`~/status` 给出本机/远端身份、会话、当前路径、有效邻居、RTT、各源观测有效期及
实际转发/拒收/无路由计数。路由可用和观测有效分别呈现；心跳不代表定位有效。
源观测 1 s 失效；同会话源时间必须递增且坐标系保持一致。

## 边界

签名提供来源认证和完整性，不提供加密；保密链路另用受管 VPN。
成员公钥代表管理员信任，不能证明成员发布的物理位置真实。
单包最多 1200 字节，成员最多 16；每次调度最多读 32 包、验签每秒最多 300 包
（初始突发 300），内核接收缓冲请求 256 KiB，超量数据丢弃并计数。
每源只保留最新路由、源时间和状态，重启会话最多退役 64 个后需维护接收端。
防重放状态仅在当前进程生命周期内保存，接收端重启后仍依赖短 UTC TTL。
只传里程计；不提供任意命令、解锁、起飞、控制权转移或飞行指令的网络入口。

## 验证

CTest 覆盖双向边、分区、到期、替代路径、配置隔离和真实签名的多跳时间/防重放边界。
阶段验收启动四个已安装节点组成菱形网络，独立 ROS 订阅者逐字段验证输出，
通过中继暂停、恢复和重启验证实际 UDP 路由收敛与无陈旧数据重发；结果保存在
`artifacts/stages1-3-20261028`，硬件射频链路不由回环网络测试替代。
