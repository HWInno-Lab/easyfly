# 算法调整后的 UI 接入

UI 管理 ROS 功能节点与运行方案，计算库继续由节点内的适配器调用。
`src/algorithms` 中的普通库无需分别创建进程；目录存在也不表示插件已注册。

## 配置和启停

在“连接与仿真 → 算法配置”设置目标检测计算设备、导航策略，以及
椭圆和彩线检测。几何检测支持选择前视/下视图像、显式光学坐标系、有效期、
线程/数量预算和各自阈值。参数范围来自 `easyfly_params/config/algorithm_ui.json`，
Qt 表单、配置校验和启动校验共用这份描述。

算法设置随连接保存，并参与生效配置摘要。旧配置缺少算法字段时保持原默认行为，
不改变旧配置摘要。使用本机仿真模式时，新算法节点随整个受管会话启动和停止，
不会发送飞行目标。运行中锁定配置，结束会话后保存、重新启动生效。
本机通信和 DDS 观测模式不创建算法进程。连接页的“远端算法管理”通过独立 HTTPS 服务管理远端管理员预置的算法；需要平台身份、私有凭据及明确启停，失联不会自动停止进程。见[远端管理部署和会话规则](../easyfly_connection_manager/REMOTE.md)。

CPU/CUDA 是检测器的请求配置，实际 provider 仍由检测器诊断报告；请求 CUDA
不可用时保留已有 CPU 回退行为。导航策略的“跟随运行方案”保留原默认选择。
基础仿真不包含感知/导航链路，降落开发准备也不包含完整精准降落。

## 结果和任务依赖

“相机与感知”增加同帧椭圆、彩线显示和算法/任务接口观测。
新输出使用 `/ellipse_observations` 和 `/color_line_observations`，绑定所选相机，
只显示源 header、图像尺寸、观测会话和时钟 epoch 匹配的图像。
结果过期、失效、时钟暂停/回退或缺少同帧图像时清除；重复帧不会延长寿命。
UI 对几何结果采用至多 0.5 秒的显示窗口。有效空结果与无效结果分别显示。
分数沿用各算法语义，不能将拟合质量视为检测概率。
这些输出没有米制深度、导航 Action 或自动巡线能力，不改变原始录像像素。

任务中心读取已审阅的实际步骤，检查对应 takeoff/goto/navigate/track/search/
precision_land/land 接口。缺失或观测过期时禁止新启动确认，并显示缺失项。
接口可发现仅是前置检查；算法输入有效性、能力状态、飞行准入和所有权仍由后端检查。
此检查不启动算法、不代替飞行确认，也不绕过既有未决/取消排空保护。

## 安装和验证边界

新增消息只追加类型，原消息字段不变。UiSnapshot 扩展后的 bridge SONAME 和
桌面快照协议均为 3；桌面、桥接及消费者必须一起构建，连接管理拒绝旧快照协议。
当前部署使用单独 UI 安装叠加 ALG-9 的算法安装，主工作区 install 不覆盖。

本次 UI 适配不关闭 ALG9-SEMANTIC-EXIT、ALG9-DDS-READER 和算法全量规范欠账。
界面回归与短时仿真不能替代这些问题的修复、长稳或实机验证。

本轮受管仿真中，椭圆/彩线各收到 36 个有效空结果，源图像 header/尺寸匹配，
两项能力均报告 ready；完整感知/规划链路出现后，工作窗口与后台正常关闭，launch 退出 0。
没有发送解锁或飞行目标。另一轮在组件仍加载时停止，launch_ros 的异步加载抛出
InvalidHandle，launch 退出 1；新检测节点和其余所属进程均退出。
这是新增的启动期停止竞态记录，未作为正常关闭通过，也未通过等待或复跑将其关闭。

2026-10-24 的 B-05 专项已复现并修复此竞态：六个项目组件入口改用
`easyfly_launch` 的事件循环加载器，停止时不再让后台线程继续访问已销毁的客户端。
缺服务、回复未到、加载完成、组件拒绝和作用域参数五个分支通过；真实受管后端在
检测组件开始构造、加载回复尚未到达时停止，launch 和全部已启动子进程正常退出。
原失败记录保留，未修改系统 `launch_ros`。详见

## SLAM 配置

连接与仿真 → 算法配置 → SLAM·定位与建图。当前接入 FAST-LIO，使用已安装的 MID-360 配置。

- 跟随运行方案：基础仿真不启动 SLAM；感知、导航和降落准备方案随会话启动 FAST-LIO。
- FAST-LIO：明确要求启用；基础仿真方案下会提示先切换运行方案。
- 关闭 SLAM：不启动 FAST-LIO 及 map→odom 集成；依赖其点云、定位的建图和导航可能无法就绪。

界面可配置 Livox CustomMsg 雷达话题、sensor_msgs/Imu 话题，并展开采样间隔、最大迭代次数、
扫描/地图体素大小、最小有效距离、最大探测距离。参数经校验后覆盖 MID-360 YAML 中对应项；
其他标定与传感器类型沿用该仿真模型的安装配置。只保存不会启动节点，生效会话中的字段保持冻结。

外部平台使用 DDS 观测，UI 不远程启动 SLAM。原始话题输入不意味着建图质量或导航准入已经就绪。
新增字段使用默认值时不写入配置，已有算法配置与会话身份摘要保持兼容。


## OpenVINS 定位观测

SLAM 选择增加 `OpenVINS（Gazebo 单目，仅观测）`，使用前视彩色图像和
Livox IMU 的固定标定。该选择仅支持非基础仿真方案，与 FAST-LIO 互斥。
D435i 实机仍需设备标定；FAST-LIO 参数不能用于 OpenVINS。

“相机与感知 → 算法与任务接口”显示启动定位源、OpenVINS 会话/代次、
输入等待、初始化、估计、过期及重启要求。估计状态只表示输出新鲜，
不表示视觉质量、机体位姿或导航就绪。状态使用 0.5 秒接收/源时间窗口，
暂停、时钟回退、多发布者、无效消息和断开均不能保持有效显示。

OpenVINS 输出仍是 `openvins_odom` 中 IMU 原点的局部位姿，尚未接入 PX4
`odom` 和占据地图。选择它时不会启动 A* 私有后端、局部规划器、跟踪器
和避障监督器；保留的导航入口明确拒绝目标。任务中心在确认前阻止导航、
跟踪、搜索步骤。默认 FAST-LIO 启动和原有 PX4 飞控遥测不受此选择替换。
