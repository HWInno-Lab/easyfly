# 机载平台：设备、算法与受管任务

EasyFly 可以保存完整的机载运行方案，并由机载后台服务按依赖统一启动飞控通信、传感器和算法。地面端与机载本机使用同一管理界面。日常运行无需逐个打开算法终端。

主路径是“连接管理 → 平台启动与管理 → 机载平台”，在主窗口内显示“运行环境”“设备管理”“算法配置”“平台状态与故障”。“接入与调试”组保留连接 DDS 和飞控通信调试。机载任务统一使用“任务中心”的“任务与执行”“任务编辑”两个页签，顶部选择任务目标。与机载管理共享同一个连接、认证平台身份和请求状态；切页或切换任务目标不会重新连接、启动、停止或取消任务。

## 首次部署

1. 在机载电脑安装本版本 EasyFly 及所选算法、传感器驱动。打开 EasyFly，在“连接管理”点击“机载平台”，直接进入当前窗口内的机载管理页。无界面机载电脑可在部署阶段完成下述配置后只运行后台服务。
2. 展开“首次部署与本机服务设置”，首次初始化前选定 ROS domain；需要实际提交任务时勾选“首次部署允许受管任务执行”。填写地面电脑能访问的机载 IPv4/DNS 地址；留空则只允许本机管理。点击“初始化 / 连接本机平台”，程序生成私有凭据并启动管理服务。本机指当前运行界面的电脑；已有部署复用原配置。首次新部署尚不启动设备或算法；如果已保存方案启用了服务启动自启，启动已有服务时可能按该设置运行模块，但不执行任务。
3. 在“设备管理”的“飞控通信”“传感设备”“标定与坐标”三个可折叠分类中选择组件，分别勾选启用并配置参数，在“算法配置”按定位建图、地图处理、导航规划、图像感知或运行服务选择组件。界面显示依赖变化和最终启用清单；导航策略为 A*、EGO、A* + EGO 单选，需要配合的组件可以共同运行。外部已提供的传感器输入可按方案配置取消对应驱动，但任务执行所需的核心链路必须归本平台管理。
4. 默认使用内置模板，在“参数配置”右侧点击“编辑”，于第三栏填写参数，保存时自动生成所需 ROS 参数文件；也可点击旁边的“上传”选择自定义文件。串口地址、雷达扫描设置、外参等按实际设备填写；FAST-LIO 扫描类型、时间单位与频率、雷达到 IMU 外参，以及 map→odom 的 `body_to_base_translation` 均有必填提示。Livox 的实际设备 JSON 和相机专用标定文件仍需单独提供。
5. 点击“保存到目标平台”，再点击“检查设备与依赖”。保存只更新已保存方案，不启动平台；检查验证安装、文件、参数和依赖，不证明真实传感器已工作。缺项会显示具体原因。
6. 点击“启动平台”，确认目标、方案版本和模块清单。服务逐个等待所需输出或节点，状态区分启动中、等待数据、就绪、降级与失败；发生失败保留所属进程与日志，便于排查。在“平台状态与故障”选择模块，点击“读取模块日志”，可展开原始状态详情。平台服务启动不会自动提交飞行任务。

默认部署目录为 `~/.config/easyfly/onboard/`，包含 server/client 配置、私有凭据、硬件配置和持久运行状态。`EASYFLY_ONBOARD_CONFIG_ROOT` 可在部署时指定其他私有目录。首次初始化的 domain、地址和任务执行授权会保留；再次连接不会用表单的首次部署字段覆盖已有配置。改变这些部署参数需在平台正常停止后由部署人员修改 `server.json` 并重启服务，同时保持证书地址和客户端配置一致。

本版本提供 19 个模块适配：MAVROS/状态桥、RealSense、Livox、相机标定 TF、飞控里程计变换、FAST-LIO、map→odom、目标检测、跟踪、像素转三维、点云过滤、语义地图、A* 导航协调、EGO 局部规划、飞控控制、任务状态机、任务服务、彩线检测和椭圆检测。导航适配支持 FAST-LIO 与 A*/EGO/组合策略；选择 EGO 或组合时会关联局部规划依赖，后台校验缺失组件并保证启动顺序。坐标对齐不作为另一种 SLAM；检测、跟踪、三维定位可以形成处理链，彩线和椭圆等不同用途可按方案并行。其他仿真 SLAM 后端尚不能直接套作机载适配，本次未新增 EGO 数值参数面板或同算法的多相机实例。

“就绪检测话题”只指定服务观察的输出；修改时必须同时通过模块参数或高级方案中的 remappings 对齐实际 ROS 话题。高级 JSON 可编辑原生参数、remappings、启动等待时间和依赖，不接受任意命令或包名。ROS 参数文件使用对应节点名或 `/**` 作用域；所有机载节点使用系统时间，文件不得开启模拟时间。上传的配置限制为 YAML/JSON 文本；已有机载文件必须位于服务配置允许的目录内。

## 参数模板与自定义文件

新方案的参数配置默认使用“内置模板”，方框右侧并排提供“上传”“编辑”。点击“编辑”在第三栏显示当前组件参数，设备页可“收起编辑”，算法页可“返回说明”；收起、切换组件后修改仍保留。模板与表单共用当前组件的参数；编辑栏内的“恢复模板”只恢复当前组件，不改变其他模块、启用状态或目标平台。尚未填完硬件信息时可保存本地草稿。

点击“保存到目标平台”后，服务在同一次版本校验和配置提交中，为已启用的模板组件生成受管参数文件，并回填路径。文件与当前参数保持一致；保存不会启动模块。普通 ROS 节点使用 ROS YAML，RealSense 按驱动要求使用平铺 YAML；飞控通信与 EGO 局部规划直接使用启动参数，不生成不适用的参数文件。

选择“自定义文件”可继续使用自己的文件，也可直接点击“上传”，成功后自动切换来源。上传取消或失败不会改变当前模板及参数；切换自定义来源时会移除自动模板参数，保留需要单独明确设置的导航策略和设备／标定文件路径。普通组件编辑栏显式列出的表单参数覆盖文件同名项；RealSense 的自定义文件优先，界面会显示相应说明。已有自定义文件方案按原规则读取。

部分模块的内部算法 YAML 仍由模块默认配置或 `config_file` 指定，ROS 参数模板只展示当前适配器实际支持的 ROS／启动参数。Livox SDK JSON 和专用相机标定文件不作为普通 ROS 参数模板生成。

模板保存需要同版本机载管理服务支持。已运行的旧服务应在平台正常停止后更新并重启；界面会说明需要更新，期间仍可编辑本地草稿和使用原自定义文件方式。

## 地面电脑管理

在机载端的首次部署区域点击“导出地面连接配置…”，选择新的空目录。将整个连接包通过可信方式交给地面电脑，在地面 EasyFly 的“连接管理 → 机载平台”点击“连接远端平台…”，选择包内 `client.json`。可以填写平台别名；导入后在常用／最近平台列表选择并点击“连接所选平台”，继续使用原服务身份校验。列表引用已有连接配置，连接包仍需保留可读。连接包包含平台 CA 和操作令牌，需保密；不包含机载服务私钥。远端操作通过校验证书的 HTTPS 执行，不使用 SSH 或远端 shell，也不会替远端自动安装或启动服务。

HTTPS 负责配置、启停、任务请求和日志；DDS 负责 ROS 状态、图像、地图等数据。管理页的“打开观察配置”准备对应的观察连接，用户核对平台身份、domain、通信范围、系统时间及相机话题后，再点击连接 DDS。仅凭相同 domain 不能验证唯一平台身份，仍须核对实际数据源；准备配置不表示已经接收到数据，也不授予任务执行权限。管理连接和 DDS 观察状态分别显示。防火墙及 DDS 跨机网络需按实际部署配置。

## 本地方案草稿与版本

机载管理页的“保存本地草稿”保存当前设备／算法方案，并兼容保留先前读取的任务副本；统一任务编辑器中的新修改需在“任务编辑”页导出为本地草稿。两种本地保存均不调用目标平台配置接口，也不启动组件或任务。“恢复本地草稿”只恢复编辑，保留原目标和方案版本；不同平台的草稿不能直接提交到当前目标，旧版本提交仍由 `expected_hash` 检查，不能静默覆盖其他客户端的修改。

本地草稿、最近平台和原任务请求记录保存在当前连接管理运行目录下的私有 `onboard-ui/` 目录。草稿不包含平台 CA、令牌或服务私钥；外部配置文件仍为原路径引用，不随草稿复制。恢复后需要核对文件是否可用。本地保存、保存到目标平台、启动平台是分别执行的操作。关闭或切换平台时遇到未保存内容，可保存本地草稿、明确放弃或返回编辑；正在处理请求时先等待结果，不通过切页丢弃请求。

## 任务配置与执行

在机载管理页点击“前往任务中心”，会选择当前机载目标并进入“任务与执行”。也可在任务中心顶部选择目标平台：

1. “任务与执行”左侧显示目标平台目录，右侧读取并审阅已保存任务；“在任务编辑中打开”将原文副本交给统一编辑器，保留注释、换行和原文哈希。
2. “任务编辑”统一新建或修改 YAML v1 任务，支持步骤表单、几何示意和高级 YAML；任务文件名始终可见。编辑只改变本地副本。
3. 在“任务编辑”中点击“保存到平台…”，窗口显示当前已校验版本、名称、哈希和实际目标，确认后“校验并保存到目标平台”。机载任务名使用 1～100 个字母、数字、下划线或横线，扩展名为 `.yaml`，完整名称的 UTF-8 长度不超过 128 字节；同名不同内容不会覆盖。机载保存无需先导出本地文件，服务仍调用原生任务校验器；平台停止时也可保存，不触发飞行。
4. 保存成功会刷新目录，可点击“查看并审阅已保存任务”定位平台版本，再读取、审阅并勾选确认，最后提交执行。快捷入口不启动任务，也不自动勾选确认。修改编辑器或切换目标会撤销旧审阅；本地校验和保存成功不会自动授予执行许可。

本机仿真／DDS 与机载平台共用这两个页签，使用各自现有通道。两种平台均可直接保存当前已校验、无未应用表单修改的版本，无需先导出本地文件；本地导出独立可选。仿真执行仍保留原有仿真／localhost 限制；机载操作继续使用认证 HTTPS 受管通道。顶部平台信息与具体操作确认均显示实际目标。

```yaml
schema_version: 1
frame_id: odom
units: {position: m, angle: rad, time: s}
failure_policy: abort
steps:
  - {type: takeoff, altitude: 1.5, timeout: 60}
  - {type: navigate, x: 1.5, y: 0.0, z: 1.5, timeout: 60}
  - {type: land, timeout: 90}
```

这是格式示例，坐标和高度需根据实际场地、定位和设备确定。读取机载已保存任务后，审阅内容并勾选确认，再点击执行。服务核对实际文件 SHA256，并通过项目的 reviewed mission 服务提交。修改编辑器会撤销原审阅。启用任务执行还需要本平台统一运行的飞控通信、坐标变换、导航、飞控控制、任务状态机和任务服务，以及唯一、新鲜的未解锁/在地面状态。QGC 转发启用时进入维护配置，禁止受管任务执行。

编辑器支持九类步骤及六个模板，提供中文名称、英文键、参数单位、范围、功能与依赖提示；未适配步骤仍可离线编辑和保存。当前机载 `track`、固定下视相机静态标记的 `precision_land`、基础模式 `explore` 已提供软件适配；需完成真实设备配置并通过启动检查。能力提示区分已适配、尚未适配、未就绪和未知，不能替代实际执行检查。提交前通过原生解析器读取实际步骤，并逐步核对方案依赖、受管组件就绪及唯一、新鲜、类型匹配的动作接口；缺项会给出原因并拒绝执行。原有地面状态、维护互斥、哈希审阅和原请求归属检查继续生效。

网络中断或请求超时后，查询原任务请求，不自动重新提交。适配器在任务提交前私有持久化原请求身份，重连或重启界面后恢复查询；未确认原任务结束前不提交新任务。取消只针对本操作者的原任务，并绑定原执行身份；需等子动作和控制权排空。关闭 UI 不取消任务，也不停止机载软件。

## 跟随、固定下视精降与自主探索

升级时为已有方案补入处于关闭状态的新组件，沿用已保存的设备和参数。三类动作使用同一受管平台和任务中心，启动组件不发送任务目标；任务仍需保存、读取、审阅及明确执行。适配状态取决于已启用组件、受管进程、真实数据和唯一动作接口，不代表实飞验收。

- **目标跟随**：启用 `target_tracking`，自动加入飞控及检测→跟踪→三维定位链。内置参数模板生成节点实际读取的 `target_tracking:` 配置，用户上传文件也使用相同范围检查和冻结。输入目标需位于 `odom`；相机内参、对齐深度及 TF 必须有效。目标丢失、异常跳变与子动作取消规则保留。
- **精准降落**：启用 `down_camera` 与 `precision_landing`，配置固定下视相机。双 RealSense 必须明确填写不同序列号。以 `easyfly_precision_landing/config/hardware_template.yaml` 为起点填写实测外参、单位四元数、光学参考系、标记尺寸／ID、落地平面和控制限制，并显式启用。将同一配置分别用于精降链的 `config_file` 和飞控的 ROS 参数文件；启动前核对两份字节一致、禁止覆盖精降关键值。硬件入口只启动标记检测、降落检测和几何变换，不启动第二个飞控或旧兼容网关。当前范围为固定相机和静态标记，动态云台与移动平台另行适配。地面启动不要求已经进入 OFFBOARD 悬停或看到有效降落目标；这些条件由精降动作执行时检查。
- **自主探索**：导航策略选择 `GCOPTER / FUEL`，加入 `lidar_rays`、`gcopter`、`fuel` 和定位／坐标依赖。填写真实雷达输入、源参考系、量程、地图边界、分辨率、机体膨胀半径及高度包络。Livox 适配只保留有效命中，每帧携带逐点采样偏移；地图按每点时刻查询 TF，缺 TF 拒绝整帧，不把空点或无回波当成空闲空间。初版采用基础 FUEL，扩展相机模式关闭，GCOPTER 与 EGO 不同时输出轨迹。地图源时间必须推进；空闲 FUEL 通过输入地图、唯一动作接口与新鲜管理响应判定就绪，不等待任务激活后才发布的策略地图。

所有硬件文件仍必须位于受管配置目录，检查后按内容冻结。证据目录由平台会话生成，不接受任意用户写入路径；上传文件与运行方案中的速度不一致时拒绝启动，避免未审阅的限值覆盖。未填写实测参数的模板会被拒绝。真实硬件接线、标定和飞行效果需在对应设备上验收，软件测试不替代这一步。

## 正常停止与自动运行

“正常停止平台”按相反依赖顺序请求正常退出，仍要求本客户端和精确受管会话。连接飞控后必须确认未解锁、在地面且没有未决任务；失联不视为停止许可，启动阶段终止继续使用原专用条件。超时保留所有权并显示未知，不强制杀进程，也不按进程名清理外部程序。管理服务异常重启时保留未决状态，不自动接管或重复启动旧进程；需查清原运行状态后处理。

勾选“服务启动时自动运行方案（不执行任务）”，保存到目标平台。平台停止时，可在首次部署区域点击“启用本机启动服务”，安装并启用当前用户的 systemd 服务。服务启动后在状态条件满足时运行已保存的算法方案，不自动执行起飞或任务。该按钮建立的是**用户服务**，通常在用户登录时启动；无人登录开机运行还需要部署人员一次性配置该用户的 linger 或适当的系统服务，本程序不自动修改系统登录策略。

无界面服务入口（安装脚本会加载对应 EasyFly 安装环境）：

```bash
/path/to/install/easyfly_connection_manager/lib/easyfly_connection_manager/easyfly_onboard_service \
  --config /home/operator/.config/easyfly/onboard/server.json
```

机载首次部署和硬件标定完成后，后续操作可全部通过管理 UI 完成。该功能已通过软件回归、真实 HTTPS/DDS、原生图像算法和真实任务服务联验；传感器输入和任务 Action 后端为测试夹具。完整硬件导航链路、具体机型标定及真机飞行尚未验收，原 `hardware_unverified` 占位状态没有改成已验证。

## 独立工具兼容入口

`ros2 run easyfly_connection_manager easyfly_onboard_manager` 继续提供原 PyQt 独立窗口，保留既有部署、方案和任务操作，作为兼容与开发入口。EasyFly 主界面采用原生 `OnboardPage` 和本地异步桥接，不通过这个工具弹出机载窗口；受管服务和 HTTPS 协议继续共用。原生页面的软件验证不替代上述硬件与具体机型验收。
