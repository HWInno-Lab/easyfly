# EasyFly 集群规划

对已启动的 `easyfly_fleet_sim` 会话执行有界多机任务。读取真实原生状态和每车
地面测量得到的 world↔odom 变换。配置中明确目标分配、世界范围、障碍、安全间距、
跟踪误差包络、速度和加速度限制。

已通过原生双机仿真验收：交叉换位、连续第二任务、最小距离任务分配、旧会话指令拒绝、
外部动作冲突拒绝、观测中断取消、不自动恢复和最终落地上锁。签收证据见工作区
`artifacts/stages1-3-20261028/swarm-signoff.json`。

```bash
ros2 run easyfly_swarm_planner swarm_mission \
  --manifest /absolute/fleet-session/manifest.json \
  --task /absolute/swap.json --output /absolute/new-review

# 添加 --execute 才会提交原生起飞、轨迹跟随和降落动作。
```

使用 `config/swap.example.json` 演示两机交换位置；`assignment: minimum_distance`
配合目标坐标数组可做最多四机的精确最小欧氏距离分配。显式分配使用车辆名到目标坐标
的映射。配置的坐标和距离均为米，时间使用共同仿真时钟。

规划采用有时间层的 A* 和逐机轨迹预留，依次尝试优先级排列。每一阶段检查整段轨迹
之间的最短距离，保护不同步运动和等待状态；最终再统一审计所有轨迹。障碍按机体半径
和跟踪误差膨胀。该有界优先级算法不保证所有存在解的问题都能求出；预算或搜索失败时
不发送飞行命令。实际起飞后用测得的悬停位置重新规划，再开始轨迹。

轨迹为每段五次平滑曲线，速度和加速度有明确上界。只有所有飞机都抵达本阶段末端，
才推进下一阶段。执行期检查实际位置到轨迹线段的距离、机间距、原生状态和时钟进展；
数据失效或脱离包络时停止流并取消本次持有的精确 Action UUID。原生飞控另有轨迹停流
看门狗，取消后保持原生悬停行为，不自动恢复旧任务。

控制器持续持有每架移动飞机的原生 `/follow_trajectory` 动作，使用各车独立导航会话。
`/flight_control/trajectory_state` 只读返回控制器会话和实际轨迹编号水位，下一任务使用
更大的编号。查询成功不代表动作准入，仍以原生 Action 回应为准。飞行控制参数和原生
安全门限不在本包中放宽。

输出保留任务审查、实际执行计划、每个原生动作 UUID／结果、最小观测间距和最终状态。
同一舰队使用独占锁和先落盘的控制账本，禁止两个协调器同时执行。响应未知时不重发动作；
退出后仍未知的账本阻止下一任务，需审计并重新启动舰队，不把客户端离线视为远端释放。
正常失败保留悬停，不隐式接管其他控制源或自动降落。独立工具可订阅共同域 `/swarm/state`
（相对领机位置、世界速度、原始观测时间）和 `/swarm/status`。

配置与离线规划支持 2–4 机；当前原生飞行签收范围为同机、受管、已知空世界中的双机
仿真，3–4 机仅完成离线规划验证，尚未签收原生飞行性能。障碍输入是
静态的保守禁入区域；不替代未知环境建图或实机避障。DDS 域隔离不提供对恶意本机发布者的
身份认证。实际无线时延、时钟同步、射频和实飞属于阶段 4。
