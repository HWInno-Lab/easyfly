# EasyFly 车辆外观重识别

已完成本地软件／渲染仿真验收。使用真实 OSNet 车辆模型输出 512 维外观特征，按余弦距离关联；
输入跟踪 ID 仅作对应关系，不参与身份判定。跨视角和遮挡质量及真实 ROS 生命周期均有独立证据。

输入为配置中 1–4 路 RGB/BGR 相机和只含当前观测的 `/tracks_raw`。必须具有完全相同的
原始 header；不能使用包含预测框的 `/tracks`。每路最多 8 辆车、4 帧缓存，最大 1920×1080。
不足 24 像素、低纹理、越界、非车辆、非有限输入拒绝提取。活动身份库最多 128 项、每项 8 个
外观样本、30 秒源／接收有效期；模糊候选和同帧争用保持未知，不强制合并。

输出 `/vehicle_identities` 使用独立 typed 消息，保留源 header、生产会话、模型哈希、
原始跟踪 ID、外观身份和距离。距离不是概率。断流／重复／过期／冻结时钟不能刷新身份；
发布源更换、重复发布者和时钟回退清空身份库并换会话。身份仅在本次生产会话内有效。
本包不修改检测器、原有 SORT ID 或飞行控制目标，车尾漏检 V-09 保持原暂缓范围。

模型来自 Open Model Zoo 的 `vehicle-reid-0001`，原模型 MIT 许可及校验来源随包安装，
启动前检查固定 SHA-256；原始 ONNX 输入为 RGB，输入 InstanceNormalization 在图内。
CPU 运行时固定 `onnxruntime==1.23.2`，每次推理最多两线程。可用 `pip --no-deps --target`
安装到独立运行目录，将该目录加入运行进程的 PYTHONPATH；保留 ROS 使用的系统 NumPy／
OpenCV，避免更换 NumPy ABI。OpenCV 4.5.4 的 DNN 不能载入该动态形状模型。

```bash
ros2 run easyfly_vehicle_reid vehicle_reid --config /absolute/reid.json \
  --gallery /absolute/enrollment.json
```

配置模板见 `config/reid.example.json`。`threshold` 和 `margin` 是可审阅的关联门限，
不会根据输入数据自动放宽。上游 VeRi 公开分数不是本地验收结果。

显式 `--gallery` 使用经人工标注的多视角参考库：v1 JSON 包含固定 `model_sha256` 和
`vehicles: [{identity, views: [{file, sha256}]}]`，每车最多 8 幅、最多 64 车，路径相对该
清单且不得越出目录。输出包含清单哈希；每次源重建保留这些固定参考，清空活动观测。
参考是身份模板，不是当前目标的位置或存在证据。只有新鲜图像匹配才能输出有效观测。
省略参考库时是保守的外观身份发现：较大视角跳变可能产生新身份或未知，不能保证自动将
未见过的正面和车尾合并；已知车辆跨视角识别使用显式多视角登记。

验收使用 7 个现有 Gazebo 车辆模型、每车 4 幅登记视角和 4 幅独立查询视角，共 56 幅
实际相机渲染图。冻结参考的离线评估：28 幅清晰查询 rank-1=100%、mAP=0.8743；左侧／底部
20% 裁剪区域遮挡与变暗变体无错误匹配，底部遮挡 1 幅保持未知。遮挡用明确记录的图像
遮盖生成；不等同真实遮挡数据。两种安装中的真实 ROS 节点处理双路相机的 112 个查询
变体，活动库正常更新，均匹配正确；批次包含 7 辆车，P95 约 109 ms。

这些数值只覆盖已登记参考的有限渲染车辆，不代表真实街景、同款同色车辆、任意镜头或
大于 20% 遮挡的准确率。无参考库的自动身份发现可能发生视角分裂，失败记录保留。
签收与原始证据见工作区 `artifacts/stages1-3-20261028/reid-signoff.json`。
